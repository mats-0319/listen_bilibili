# lb设计

## 立项原因

生活中有很多场景想要听个歌，但是现有的解决方案总有这样那样的不足，最终决定自己编程。

- 网易云音乐/QQ音乐/酷狗音乐：主流的音乐播放器面临相同的问题——曲库不全。假设我使用网易云，某天找到一首喜欢的歌，
  但是网易云没有版权，这时候我唯一能做的就是劝自己：其实我也没有那么喜欢这首歌。
  还有让人非常闹心的弹窗，每次启动app，只要你的手稍微慢一点，在点击播放按钮之前你就得先关闭会员充值弹窗，
  我试过了所有的主流音乐播放器，都是这样。
- listen 1：聚合平台，只是可以同时接入多家的音源，并没有解决曲库不全的问题，甚至一些平台还有防外部引用机制，
  例如我曾使用listen1，一首歌听着听着就变成了15秒的：'请到xx音乐手机端播放......'。
    - 这里顺便说一点，listen 1可以播放B站音源，我们最终的技术方向也是播放B站音源，看上去似乎没有必要单独编程，其实不然。
      主要区别是：listen 1播放的是B站音乐板块的音源，这是一个和B站视频板块平级的板块；而我们使用的是B站视频板块。
      B站音乐板块内容相对较少，并且更偏向ASMR、有声朗读等内容（早年间调研结果），单独的音乐板块无法支撑我们的需求。
- B站音乐视频：这里指的是B站上那些以音乐为主的视频，此类视频的图像多是一个旋转的碟片之类的、完全可以忽略。
  可以使用B站收藏夹功能当作歌单，但这样也有问题：
    - 音量：B站视频由用户上传，很可能出现前一个视频声音很小、后一个视频声音很大的情况
    - 合集：部分视频是音乐合集的形式，即一个视频中有多首音乐，收藏夹无法单独播放其中的某一首，
      而在一个100首歌的合集中找到一首不喜欢的歌可太容易了。
        - 这一点我们的程序也没有完全解决：lb可以播放那些分p视频中的单独一个page，无法只播放一个一小时的视频的中间十分钟

音源选择：

开始编程之前还有一关：选择一个免费的、相对丰富的音源/曲库。如果音源收费，那我宁可不听歌了；而曲库不全前面已经解释过了。
经过比较，选择B站视频作为音源。

## 技术调研

其实最开始我做的是web版本(go+vue)，因为熟悉相关技术。技术方案是：

1. 模拟手机端身份访问B站目标网页，拿到html文件
2. 从html中提取视频的原始地址（通常是.mp4文件）
3. 通过html video组件播放原始地址的视频
    - 还有一条路是通过iframe嵌入bv地址，但是B站不支持通过url参数调整音量，iframe也限制不能对内部网页执行js脚本

自动播放、播放声音等则通过浏览器安全设置编辑白名单。

但这终究是违规操作，并且没有任何保障，例如中间有一次B站修改数据结构，导致我提取视频原始地址的正则失效了。
我开始思考有没有合法合规的技术路线，查找资料期间，发现Android WebView相当于一个拥有管理员权限的网页，
理论上可以满足我的需求，编写demo验证通过后，开始学习Android开发。

## 需求设计与实现

1. 能播放B站视频
2. 能自动播放、连续播放、调整音量
3. 能编辑歌单

播放B站视频：webView+B站外链播放器，标准实现是中间加一层iframe，但是没有必要且不方便后续控制

视频控制：通过外链播放器参数和js监控组件共同实现：

- 外链播放器参数：自动播放、不展示弹幕、允许播放分p视频的指定page
- js监控：video准备就绪后自动播放并设置音量、video播放结束后通知flutter

注：video dom不是B站外链播放器提供的API，存在修改可能。但是我们要修改音量最方便的就是尝试去拿video dom，
所以不考虑这一风险，默认B站外链播放器不会修改video dom。

编辑歌单：可以编辑一首歌，也可以编辑整个歌单

- 编辑一首歌：编辑页面，创建、编辑、删除、排序
- 编辑歌单：在app外部存储空间拿到歌单文件，修改歌单文件并重启应用以应用修改

## 问题

2. 如何实现全局错误展示功能：无论在哪个页面，出现错误时导航到错误页面（或错误弹窗）并展示错误信息
3. 如何释放webview资源？
4. 如何实现容器不编写固定尺寸也能自适应尺寸？
